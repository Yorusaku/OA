# 全景智能 OA 开发阶段 Prompt 总览与测试指引

本目录用于存放「分阶段交给 Cursor Agent 的 Prompt」，以及每个阶段完成后你可以手动做的**最小自测流程**，确保质量可控、方便写到简历和做 Demo。

## 一、执行顺序总览

推荐按照下列顺序依次把对应 md 里的 Prompt 整段复制给 Agent（每次只做一个阶段）：

1. `phase-0-2-init-monorepo.md` Monorepo + Turborepo 基建、`apps/web` 初始化、权限壳和后台布局导航。
2. `phase-3-vue-query-server-state.md` Vue Query 接管服务端状态与 API 封装。
3. `phase-4-dynamic-form-engine.md` 动态表单引擎（JSON Schema + VeeValidate + 联动校验）。
4. `phase-5-workflow-engine.md` 可视化流程编排引擎（@vue-flow/core）。
5. `phase-6-business-modules.md` 审批中心 / 工作台 / 组织架构 / 通讯录 / 系统管理等业务模块。
6. `phase-7-performance-optimization.md` 性能与体验优化（虚拟滚动 / 懒加载 / Tailwind + Element 主题统一）。
7. `phase-8-polish-and-integration.md` 联调、统一异常处理、401 登录过期逻辑、端到端 Demo 与 README 收尾。
8. `phase-12-packages-utils-and-mock.md` Monorepo 公共包与 Mock 数据（packages/utils + axios 封装 + Mock API）。
9. `phase-9-code-quality-optimization.md` 代码质量与架构优化（类型安全 + 代码复用 + 错误处理）。
10. `phase-10-feature-enhancement.md` 功能扩展与增强（智能表单 + 审批增强 + 数据可视化）。
11. `phase-11-devops-and-documentation.md` DevOps、测试与文档完善（自动化 + 测试 + 文档）。
12. `phase-13-document-engine.md` 文档与表格引擎（Excel 导入导出 + PDF 预览）🆕。

> 使用方式：每轮开发前，打开对应 `phase-*.md`，复制文件中的整段 Prompt 粘贴给 Agent，即可约束它只做当前阶段的工作。

## 二、各阶段建议自测流程（你自己快速验收用）

### 1. 阶段 0～2：基建 + 权限壳 + 布局导航

- 从仓库根目录：
  - 运行 `pnpm install` 是否正常完成；
  - 运行 `turbo run dev --filter=web` 是否能启动前端。
- 浏览器访问前端地址：
  - 能看到登录页；
  - 登录（可用假账号）后跳到主布局，包含顶部导航 + 侧边栏 + 内容区域；
  - 切换侧边栏折叠、点击菜单切换路由，UI 状态在刷新后是否保持（若已实现持久化）。

### 2. 阶段 3：Vue Query 服务端状态与 API 层

- 打开一个使用 Vue Query 的页面（例如工作台或专门的 Demo 页）：
  - 页面加载时有明确的 loading 状态；
  - 正常返回时能展示列表/统计数据；
  - 模拟接口失败（改错 URL 或返回错误码）时，有统一的错误提示，不会白屏。
- 在浏览器网络面板中多次来回切换页面：
  - 高频数据（如字典/部门树）不会每次都重新请求，而是命中缓存；
  - 当触发某个提交操作（mutation）后，相关列表数据会自动刷新。

### 3. 阶段 4：动态表单引擎

- 打开 `DynamicForm` 的 Demo 页面：
  - 各种字段（输入框、选择器、日期等）能根据 schema 正常渲染；
  - 必填字段未填时有校验提示，填入后提示消失；
  - 更改「请假类型」「请假天数」等字段时，能触发联动必填（如“病假 → 医院证明必填”“>3 天 → 交接人必填”）。
- 检查调用方式：
  - 页面只需传入 JSON Schema 与 model，即可完成渲染与校验，不需要在业务页重复写 rules。

### 4. 阶段 5：流程编排引擎

- 打开流程列表页：
  - 能看到流程定义列表（名称、状态等）；
  - 能进入某个流程的编辑页面。
- 在流程编辑页面：
  - 能添加不同类型的节点、拖拽位置、连线、删除节点/连线；
  - 选中节点后，右侧或弹窗能编辑节点属性（名称、处理人、绑定的表单 Schema 等）；
  - 点击保存后重新打开该流程，节点与连线布局、配置能正确还原。

### 5. 阶段 6：业务模块

- 工作台：
  - 登录后能进入工作台路由，看到待办统计/快捷入口/最近审批或占位信息；
  - 刷新页面数据不会异常。
- 审批中心：
  - 能通过菜单进入“发起审批/我的申请/待我审批/已审批”等页面；
  - 发起审批：选择流程 → 动态表单正确渲染 → 提交后有反馈（mock 或真实）；
  - 在列表中能看到刚提交的记录（如果当前逻辑已支持）。
- 组织架构 & 通讯录：
  - 组织架构树能展开/收起部门，点击部门能看到成员列表；
  - 通讯录能切换视图模式、搜索人员。
- 系统管理（简化版）：
  - 能打开用户管理/角色管理等页面；
  - 至少支持查看列表，部分操作（新增/编辑）可先使用 mock。

### 6. 阶段 7：性能与体验优化

- 打开组织架构和通讯录页面：
  - 列表/树数据量较大时，滚动依然流畅，没有明显卡顿；
  - 使用浏览器 DevTools 观察 Elements，滚动时 DOM 节点数量维持在一个较小范围（说明虚拟列表生效）。
- 检查懒加载：
  - 大组件（如流程编辑器）不在首屏时，不会在初始包中加载，首屏加载体积减小；
  - 滚动到懒加载组件所在区域时，才开始加载和渲染。
- UI 一致性：
  - Tailwind 的主色、圆角与 Element Plus 组件的主题风格一致，无明显违和的默认蓝/圆角。

### 7. 阶段 8：联调、异常与收尾

- 故意让接口返回 401（或在本地模拟）：
  - 能统一走“清理 Token/用户信息 → 跳转登录 → 提示登录过期”的流程；
  - 不会出现部分页面卡在半登陆状态。
- 故意触发接口错误：
  - 有统一的错误提示（Message/Notification），而不是每个页面的弹窗风格都不一样；
  - 错误不会导致整页白屏。
- 打开 README：
  - 能一眼看懂项目做了什么、如何运行、本地启动命令和主要技术亮点；
  - 自己对照 README 能无障碍跑起来整个 Demo 流程。

### 8. 阶段 12：Monorepo 公共包与 Mock 数据

- 验证 packages/utils 包：
  - 检查 `packages/utils` 目录结构完整，包含所有工具函数、类型定义、HTTP 客户端；
  - 在 `apps/web` 中能正常导入和使用 `@oa/utils`；
  - 运行 TypeScript 编译，确保无类型错误。
- 验证 HTTP 客户端：
  - 测试请求拦截器能正常添加 Token；
  - 测试响应拦截器能正常处理响应和错误；
  - 测试 401 错误能正常跳转到登录页。
- 验证 Mock API：
  - 确保 `VITE_USE_MOCK=true` 时 Mock API 正常工作；
  - 登录接口返回 Mock 数据；
  - 所有业务页面都能正常加载 Mock 数据；
  - 检查 Mock 数据结构合理，能演示完整功能。
- 验证 API 层重构：
  - 所有 API 模块都使用新的 HTTP 客户端；
  - 所有 composables 都使用新的 API 模块；
  - 功能完整且与之前一致。

### 9. 阶段 9：代码质量与架构优化

- 运行类型检查：
  - 执行 `pnpm typecheck` 无错误；
  - 执行 `pnpm lint` 无错误或警告。
- 验证类型安全：
  - 检查表单数据和 API 响应都有完整的类型定义；
  - 检查代码中不再有滥用的 `any` 类型。
- 验证错误处理：
  - 模拟各种错误场景，确认有统一友好的提示；
  - 确认错误边界组件能正常工作，不会白屏。

### 9. 阶段 10：功能扩展与增强

- 验证动态表单增强：
  - 能够注册自定义表单组件并正常使用；
  - 能够从模板快速创建表单。
- 验证审批增强：
  - 能够在审批详情页添加和查看评论；
  - 能够上传和预览附件；
  - 能够收到审批通知并在顶部导航查看。
- 验证数据可视化：
  - 工作台能正常显示各种统计图表；
  - 图表有 loading 状态，数据加载失败有提示。
- 验证工作流增强：
  - 能够从节点模板快速添加节点；
  - 能够导出和导入工作流配置。

### 10. 阶段 11：DevOps、测试与文档完善

- 运行测试：
  - 执行 `pnpm test` 所有测试通过；
  - 检查测试覆盖率报告，核心模块达到 80% 以上。
- 查看文档：
  - 启动 Storybook，能够查看所有组件文档；
  - 查看 `docs/` 目录，架构和 API 文档完整。
- 验证 CI/CD：
  - 推送代码到 GitHub，CI 流程正常运行；
  - 能够看到代码检查、类型检查、测试的执行结果。

### 11. 阶段 13：文档与表格引擎 🆕

- 验证 Excel 导入功能：
  - 打开 `ExcelImporter` 组件 Demo 页面；
  - 拖拽上传 .xlsx/.xls 文件，能正常解析并显示数据预览；
  - 配置验证规则后，能正确标记错误数据；
  - 点击"下载错误报告"能导出包含错误信息的 Excel 文件。
- 验证 Excel 导出功能：
  - 打开 `ExcelExporter` 组件 Demo 页面；
  - 选择数据后点击导出，能下载格式正确的 Excel 文件；
  - 自定义列配置后，导出的 Excel 列顺序和格式符合预期。
- 验证 PDF 预览功能：
  - 打开 `PdfViewer` 或 `DocumentPreview` 组件 Demo 页面；
  - 加载 PDF 文件后能正常渲染；
  - 缩放、翻页、旋转操作流畅；
  - 点击打印/下载按钮能正常触发浏览器功能。
- 验证统一文档预览：
  - 使用 `DocumentPreview` 组件，传入 Excel 和 PDF 文件；
  - 组件能自动识别文件类型并正确渲染；
  - 无需手动指定 `type` 属性。
- 验证性能：
  - 上传大文件（10 万 + 行 Excel），UI 不卡顿；
  - 打开大 PDF 文件，渲染流畅；
  - 使用浏览器 DevTools 查看，Worker 线程正常工作，主线程无阻塞。
- 查看文档：
  - 打开 `apps/web/src/components/document/README.md`；
  - 能够快速找到 API 文档和使用示例。
