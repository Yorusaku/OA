```text
你现在是编码 Agent，请严格按照下面项目说明和约束开发代码。

【一、项目背景】
- 项目名称：全景智能 OA 协同办公平台（企业级 OA / 人事协同中台）。
- 当前状态：阶段 0～9 已完成，包括：
  - 完整的架构、权限引擎、动态表单、工作流引擎、性能优化、代码质量提升等。
- 本轮目标：功能扩展与增强，让产品从"可用"升级为"好用"，增加核心竞争力功能。

【二、技术与优化方向约束】
- 功能方向：
  - 动态表单引擎增强：支持自定义组件注册、智能表单推荐、批量导入导出；
  - 审批功能增强：添加审批评论、附件上传、流程实时通知；
  - 数据可视化：集成图表库，实现审批数据统计分析和自定义仪表盘；
  - 工作流引擎增强：支持节点模板、流程导入导出、版本管理。
- 技术约束：
  - 使用 ECharts 作为图表库，保持轻量和高性能；
  - 附件上传支持本地预览和 OSS 上传（mock 实现）；
  - 通知系统使用 EventBus 或 Pinia 实现，保持简单可靠。

【三、本次要完成的阶段/范围】
仅实现《开发计划》中 **阶段 10：功能扩展与增强**，包含：

1. 动态表单引擎增强
   - 自定义组件注册机制（位于 `@/components/dynamic-form/registry.ts`）：
     - 提供 `registerFormComponent` 函数，允许业务方注册自定义表单字段；
     - 支持组件的 props、emits、slot 等配置；
     - 内置示例：图片上传、签名板、富文本编辑器（使用简单的 mock 实现）。
   - 表单模板功能：
     - 创建常用表单模板库（请假、报销、采购等）；
     - 支持从模板快速创建新表单；
     - 模板支持自定义配置和保存。
   - 表单数据导入导出：
     - 支持 Excel/CSV 格式的表单数据批量导入；
     - 支持表单数据导出为 Excel/CSV 格式；
     - 使用 xlsx 库实现（轻量级，mock 验证）。

2. 审批功能增强
   - 审批评论功能：
     - 在审批详情页添加评论区，支持文字评论；
     - 评论支持 @ 提及用户和表情（简单实现）；
     - 评论按时间倒序排列，支持分页加载。
   - 附件上传功能：
     - 在表单中添加上传组件，支持图片、PDF、Word 等格式；
     - 附件支持预览（图片直接预览，其他文件用图标表示）；
     - 实现 mock 的 OSS 上传逻辑，模拟真实上传流程。
   - 审批通知系统：
     - 创建 `useNotification` composable 管理通知；
     - 新审批、审批通过/驳回时自动推送通知；
     - 顶部导航栏添加通知图标和小红点提示；
     - 通知支持标记已读和全部已读。

3. 数据可视化仪表盘
   - 集成 ECharts 图表库：
     - 在 `apps/web/package.json` 中添加 echarts 依赖；
     - 创建 `@/components/charts/` 目录，封装常用图表组件；
     - 封装 `useECharts` composable，统一管理图表实例和响应式更新。
   - 工作台数据统计：
     - 待办审批数量统计卡片；
     - 审批通过率趋势图（折线图）；
     - 各部门审批数量对比图（柱状图）；
     - 审批类型分布图（饼图）。
   - 自定义仪表盘功能（简化版）：
     - 支持拖拽调整图表位置；
     - 支持添加/删除统计卡片；
     - 配置保存在本地 localStorage 中。

4. 工作流引擎增强
   - 节点模板库：
     - 创建常用节点模板（审批、抄送、条件分支、结束等）；
     - 支持从模板快速添加节点；
     - 节点模板支持自定义配置。
   - 流程导入导出：
     - 支持将工作流配置导出为 JSON 格式；
     - 支持从 JSON 文件导入工作流配置；
     - 导入时进行数据校验，防止错误配置。
   - 流程版本管理（简化版）：
     - 支持保存流程的多个版本；
     - 支持查看历史版本和回滚；
     - 版本信息保存在 mock 数据中。

【四、实现与代码质量要求】
- 功能扩展必须是"渐进式"的：
  - 优先实现核心功能，复杂功能可以简化或 mock；
  - 保持现有 API 稳定，不破坏已有功能；
  - 新增功能要有清晰的注释和使用说明。
- 第三方库集成必须是"轻量级"的：
  - ECharts 按需引入，只导入需要的图表类型；
  - xlsx 库按需引入，只在需要导入导出时加载；
  - 避免引入过重的依赖，保持包体积可控。
- 用户体验必须是"流畅"的：
  - 图表加载要有 loading 状态；
  - 附件上传要有进度提示；
  - 通知推送要有动画效果，不突兀。
```
