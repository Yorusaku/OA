# 阶段 6 Prompt：业务功能模块（审批中心 / 工作台 / 组织架构 / 通讯录 / 系统管理）

> 用途：交给 Agent 的完整指令，让它只实现「阶段 6」——在已完成引擎与基础架构的前提下，按模块完成核心业务页面与功能。

```text
你现在是编码 Agent，请严格按照下面项目说明和约束开发代码。

【一、项目背景】
- 项目名称：全景智能 OA 协同办公平台（企业级 OA / 人事协同中台）。
- 目前仓库已完成阶段 0～5：monorepo 基建、权限与布局、Vue Query 服务端状态、动态表单引擎、流程编排引擎。
- 本轮目标是围绕「审批中心 + 工作台 + 组织架构 + 通讯录 + 系统管理」等模块，落地一批可 demo 的业务功能页面，真正证明前面引擎和架构的价值。

【二、技术与架构约束】
- 必须沿用既有架构理念：
  - 服务端状态全部由 Vue Query 管理；
  - Pinia 仅做 UI/会话状态。
- 动态表单与流程引擎已经存在，本轮要「复用」它们，而不是重新造轮子。
- 路由与权限：
  - 各业务模块页面需要挂接到已有的动态路由与菜单体系；
  - 按计划中的 RBAC 模型控制谁能看到/操作哪些功能。

【三、本次要完成的阶段/范围】
- 仅实现《开发计划》中 **阶段 6：业务功能模块**，建议优先级顺序如下（如时间不够可按顺序裁剪）：

1. 工作台（Dashboard）
   - 路由与菜单入口：如 `/dashboard`。
   - 功能：
     - 展示当前用户待办数量、已申请数量等概要统计；
     - 快捷入口卡片（发起审批、进入审批中心、查看通讯录等）；
     - 最近审批/申请列表（调用 Vue Query hooks）。

2. 审批中心
   - 路由结构建议：
     - `/approval/launch`：发起审批；
     - `/approval/mine`：我的申请；
     - `/approval/todo`：待我审批；
     - `/approval/done`：我已审批。
   - 功能要点：
     - 「发起审批」：选择一个流程定义（来自 Workflow 模块）→ 根据流程节点绑定的表单 Schema 拉取 schema → 使用 DynamicForm 渲染并提交；
     - 列表页（我的申请/待我审批/已审批）：基于 Vue Query 的分页/筛选；
     - 详情页：展示审批单详情 + 流程流转记录（可以先用 mock 数据，占好 UI 结构）。

3. 表单/流程配置入口（如果阶段 5 已经有基础，可在此稍作完善）
   - 在侧边菜单中增加「表单配置」「流程配置」入口；
   - 表单配置：表单 Schema 列表（增删改查）、可先仅支持 JSON 编辑，对接 DynamicForm；
   - 流程配置：复用阶段 5 的 WorkflowList 与 WorkflowEditor 页面。

4. 组织架构
   - 路由：如 `/org/tree`。
   - 功能：
     - 使用 Element Plus 的 Tree 或自定义组件展示部门树；
     - 点击部门节点展示部门成员列表（可使用 Vue Query 从 `/dept/tree` 或 `/user/list` 中获取/过滤）；
     - 为后续「虚拟滚动/懒加载优化」预留数据结构（暂不强制实现 useVirtualList，本轮可先做正常树）。

5. 通讯录
   - 路由：如 `/contacts`。
   - 功能：
     - 展示人员列表，支持搜索（姓名/工号/部门）；
     - 切换「列表模式 / 树模式」（视图切换即可，数据可以共用组织架构的数据）；
     - 使用 Vue Query 管理列表数据与搜索参数。

6. 系统管理（简化版）
   - 路由：如 `/system/users`, `/system/roles`, `/system/menus`, `/system/dicts`。
   - 简化目标：
     - 用户管理：展示用户列表，支持简单的新增/编辑/禁用（可先用前端 mock 或部分 mutation 示例）；
     - 角色管理：展示角色列表和已分配的权限码（仅展示或支持简单编辑均可）；
     - 菜单/权限配置：展示菜单树与绑定的权限码（可以先只读，为后续实际后台实现留接口）；
     - 数据字典：展示字典类型和字典项列表，配合之前设计的 `useDictByType` 等 hooks。

- 不需要一次性实现所有复杂交互（比如完整的权限编辑弹窗），但需要把路由、菜单、基础页面骨架和 1～2 条真实数据流（通过 Vue Query）跑通。

【四、实现与代码质量要求】
- 所有页面的数据来源必须经过既有 API 封装 + Vue Query，不允许在组件内直接写 axios 调用。
- 动态表单与流程引擎务必被复用：
  - 发起审批页面必须通过流程定义 + 节点绑定的 schema id，调用 DynamicForm 渲染表单；
  - 流程配置入口必须使用 WorkflowCanvas。
- 路由和菜单要与 RBAC 一致：
  - 为每个新页面设计合理的权限码（如 `approval:launch`、`org:view`、`system:user:edit` 等）；
  - 确保 `v-auth` 应用于关键按钮（如“发起审批”“新增用户”等）。
- UI 不求花哨，但要保持清晰、分区合理，方便你在面试中 demo。

【五、你在这轮需要输出什么】
- 列表说明：
  - 新增了哪些业务页面（路径 + 功能简介）；
  - 新增或调整了哪些 API / Vue Query hooks；
  - 菜单与路由上如何挂接这些模块（包括权限码）。
- 给出至少 1～2 个「端到端」使用链路的关键代码（例如“选择流程→加载 schema→DynamicForm 填写→提交 mutation→刷新待办列表”）。
```
