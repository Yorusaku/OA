# ADR-003: 流程发布与回滚策略

## 状态
已采纳（2026-05-13）

## 背景
当前流程管理仅支持编辑和删除，缺少企业级流程治理必需的"发布→审核→回滚"闭环。需要在两周内落地可演示的版本治理能力。

## 决策

### 1. 版本化策略：全快照式（Snapshot）
**选择：** 每次创建、更新、发布、回滚均生成完整快照版本

**理由：**
- 全快照保证了回滚的原子性和可验证性——回滚到任意版本时流程定义完整还原
- 实现简单，适合 MVP 阶段快速交付
- 版本列表展示操作人、时间、备注，满足"可追溯"演示需求

**放弃的方案：** Diff 增量存储 —— 在内存存储模式下增加复杂度且无明显收益。

### 2. 回滚策略：版本可选 + 风险提示 + 操作确认
**选择：** 回滚对话框展示版本列表（含版本号、操作人、时间、状态），用户选择目标版本后二次确认

**要素：**
- 版本列表显示每条版本的状态（草稿/已发布/已回滚）
- 风险提示：明确告知回滚将立即覆盖当前配置且不可逆转
- 二次确认：用户必须点击"确认回滚"完成操作

**放弃的方案：** "盲回滚"（点击按钮直接回滚到上一版本），缺乏可解释性，面试演示时会是短板。

### 3. 发布前影响分析
**选择：** 发布前展示关联审批影响——待处理审批数、涉及节点数、风险等级、操作建议

**风险判定规则：**
| 待处理审批数 | 风险等级 | 建议 |
|-------------|---------|------|
| ≥20 | 高 | 建议错峰发布、灰度 |
| 5-19 | 中 | 建议低峰期发布、通知审批人 |
| <5 | 低 | 可直接发布 |

**放弃的方案：** 复杂的依赖图和节点变更可视化 —— 两周排期内做不到。

### 4. 发布/回滚审计追踪
**选择：** 每次发布和回滚操作自动写入审计日志，记录操作人、IP、UA、耗时、关联链接

**理由：** 形成"谁何时发布了/回滚了哪个流程"的完整证据链，是"可演示企业治理"的核心闭环。

## 影响
- BFF 新增 `GET /api/v1/workflow/:id/versions` 接口
- BFF 新增 `POST /api/v1/workflow/:id/publish` 和 `POST /api/v1/workflow/:id/rollback` 审计写入
- 前端新增版本历史、回滚、影响分析对话框
- 回滚操作携带审计事件，可被审计日志页检索
